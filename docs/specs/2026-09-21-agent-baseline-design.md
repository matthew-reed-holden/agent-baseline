# agent-baseline — design

**Status:** approved in discussion 2026-09-21, pending spec review
**Repo:** `matthew-reed-holden/agent-baseline` (public, GitHub template)

## Goal

One repo-tracked baseline for AI-agent configuration that works identically
across Claude Code, Codex and OpenCode, can be applied to a new repo or
re-applied to an existing one, and reports drift. It carries the *repo* layer
only; per-user config (global instructions, plugin allowlist, user-scope MCP,
secrets, model defaults) stays in the user's home-manager setup.

Rule of thumb: if an agent in a fresh clone on a machine you do not own needs
it, it is repo-tracked and belongs here. Otherwise it is not.

## Non-goals

- Stack tooling (CI, Makefile, turbo, linters). Each repo owns its own.
- Beads formulas, agent definitions with model routing, docs hosting. Those
  are later sub-projects; this repo reserves their locations.
- Managing anything under `$HOME`.
- Storing secret values. Ever.

## Layout

```
agent-baseline/
  README.md                 one page: purpose, apply/check, owned vs seeded, refresh steps
  apply.sh                  entry point (bash)
  render.py                 generator (python3, stdlib only)
  manifest                  one line per file:  <path>  owned|seeded
  baseline/
    AGENTS.md               seeded  skeleton, headed sections + fill hints
    CLAUDE.md -> AGENTS.md  owned   symlink
    .mcp.json               seeded  {"mcpServers": {}} — the single MCP source
    .beads/PRIME.md         owned   workflow + policy + session-close (SSOT for bd prime)
    .beads/formulas/        owned   empty (.gitkeep) until the beads-workflows sub-project
    .codex/hooks.json       owned   vendored output of `bd setup codex`
    .agents/skills/beads/   owned   vendored output of `bd setup codex`
    agents/README.md        seeded  where harness-agnostic agent defs will live
    docs/README.md          seeded  docs index stub (architecture.md, runbooks/, specs/)
  overlays/
    go/.mcp.json            seeded  postgres server, `${DATABASE_URL:-<default>}`
    go/overlay.json         plugins + vars (below)
    node/.mcp.json          seeded  shadcn, storybook, next-devtools
    node/overlay.json       plugins + vars
  test/                     fixture repo + expected render; `apply.sh --self-test`
```

Overlay seeds win over baseline seeds for the same path.

### Generated files (header: `# generated by agent-baseline — edit .mcp.json instead`)

| File | Source |
|---|---|
| `.codex/config.toml` | `.mcp.json` → `[mcp_servers.*]`, plus `[features] hooks = true` |
| `opencode.json` | `.mcp.json` → `mcp` |
| `.claude/agents/*.md`, `.opencode/agents/*.md` | `agents/*.md` (model map applied; empty until the model-routing sub-project) |

### Merged file

`.claude/settings.json` — apply owns exactly three keys and leaves the rest
(permissions, statusline, anything the user added) untouched:

- `hooks.SessionStart` = `[{ matcher: "", hooks: [{ type: "command", command: "bd prime --hook-json" }] }]`
- `enabledMcpjsonServers` = keys of `.mcp.json`
- `enabledPlugins` = overlay `plugins`, each `true`

### Not touched

`.beads/config.yaml` is bd-owned. Apply appends `agent.profile: team-maintainer`
only if no `agent.profile:` line exists.


Overlay `.mcp.json` files are seeded by virtue of the overlay; they need no
manifest line.

## Overlay format

```json
{
  "plugins": ["gopls-lsp@claude-plugins-official"],
  "vars": [
    { "name": "DATABASE_URL_DEFAULT",
      "prompt": "Local Postgres URL used when DATABASE_URL is unset",
      "default": "postgres://localhost:5432/postgres",
      "targets": [".mcp.json"] }
  ]
}
```

Baseline vars (always asked on first seed, any stack): `PROJECT_NAME`,
`PROJECT_SUMMARY` (one sentence), `PR_TARGET_BRANCH` (default `main`).
Targets are seeded files only; a var is substituted as `{{NAME}}` at seed
time. Owned and generated files never contain vars.

## `apply.sh`

```
apply.sh [--stack go|node] [--check] [--yes] [--var NAME=VALUE]... [--self-test] [DIR]
```

Requires: bash 4+, python3, git. `jq` is not required (render.py does JSON).

1. **Resolve** `DIR` (default `.`); refuse if not a git repo.
2. **Answers** — load `.agent-baseline` if present (previous answers, template
   SHA, stack). For each var without an answer: `--var` wins, then `--yes`
   takes the default, else prompt on the TTY showing the default. Non-TTY
   without `--yes` is an error listing the missing vars.
3. **Copy** — owned: overwrite (directories replaced whole). Seeded: copy only
   if absent, substituting `{{VAR}}`. Overlay files layered after baseline.
4. **Render** — `render.py DIR` reads `.mcp.json` and `overlay.json`, writes
   the generated files and merges `.claude/settings.json`.
5. **Env check** — every `${VAR}` / `${VAR:-default}` referenced in `.mcp.json`
   is looked up in the environment; print ✓/✗ per var with a one-line hint
   for ✗. Missing vars do not fail apply (they fail at MCP spawn, which is the
   honest place), but they do print in red.
6. **Stamp** — write `.agent-baseline` (JSON: template commit SHA, stack,
   answers, timestamp).

`--check`: run steps 3–4 into a temp copy, `diff -ru` against `DIR`, run the
env check, exit 1 on any drift or missing var. Prints the diff. Intended for
a CI step and for "is this repo current?".

`--self-test`: apply into a temp dir from `test/fixture/` and diff against
`test/expected/`; exit non-zero on mismatch. This is the one runnable check
the generator leaves behind.

## `render.py` mapping rules

`.mcp.json` follows Claude Code's schema: `mcpServers.<name>` with
`type: stdio|http|sse`, `command`, `args`, `env`, `url`, `headers`.
Env references are `${VAR}` or `${VAR:-default}`.

| `.mcp.json` | `.codex/config.toml` | `opencode.json` |
|---|---|---|
| `type: stdio`, `command`, `args` | `command = …`, `args = […]` | `type: "local"`, `command: [cmd, …args]` |
| `type: http` / `sse`, `url` | `url = …` | `type: "remote"`, `url` |
| `env.K = "${V}"` | `env_vars = ["V"]` (K must equal V; else hard error unless a default is given) | `environment.K = "{env:V}"` |
| `env.K = "${K:-d}"` (key = var) | `env_vars = ["K"]` + `env.K = "d"` | `environment.K = "{env:K}"` (no default; noted in env check) |
| `env.K = "${V:-d}"` (key ≠ var) | `env.K = "d"` — Codex cannot remap; default only | `environment.K = "{env:V}"` |
| `env.K = "literal"` | `env.K = "literal"` | `environment.K = "literal"` |
| `headers.Authorization = "Bearer ${V}"` | `bearer_token_env_var = "V"` | `headers.Authorization = "Bearer {env:V}"` |
| other `headers.H = "${V}"` | unsupported: hard error | `headers.H = "{env:V}"` |

Anything render.py cannot express in a target format is a hard error naming
the server and field — silent lossy output is how drift starts.

TOML is emitted by a 30-line writer (strings, string arrays, string tables);
no third-party dependency.

## Rollout

1. Create the repo; build `apply.sh`, `render.py`, baseline, overlays, fixture.
2. `apply.sh --check --stack go ../theostack/theostack-go-hygiene` and the
   node equivalent: validates manifest and generator against real repos.
3. `apply.sh --stack go|node` onto the two hygiene branches. Expected diff:
   new `opencode.json`, regenerated `.codex/config.toml` and
   `.claude/settings.json` (content-equivalent to the hand-written ones),
   new `.agent-baseline`. Push as follow-up commits on the open PRs.
4. Verify: `bd prime` output unchanged; `codex mcp list` shows the rendered
   servers; `opencode.json` parses; `apply.sh --check` exits 0 in both repos.

## Verification for this spec's implementation

- `apply.sh --self-test` green.
- `--check` is idempotent: apply, then check, exits 0.
- Rendering the current theostack-go `.mcp.json` yields a `.codex/config.toml`
  whose `codex mcp list` output matches today's.
- A `${VAR}` with mismatched key/var name, and an http server with a
  non-Bearer header env ref, each produce a hard error naming the server.
